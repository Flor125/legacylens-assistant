# Legacy → Modern Equivalence Baseline

## Objective

Establish a reproducible baseline showing that the modern Python
implementation preserves the observable cost-calculation behavior
of the legacy COBOL program.

## Legacy component

Program:

`legacy/cobol/batchcosto.cob`

The COBOL program processes cost records grouped by product and
calculates a weighted average cost:

```
total cost value / total quantity
```

The resulting values are written to `historico.dat`.

## Test dataset

The validation fixture contains 10 cost records across 5 products.

The COBOL program produces the following average costs:

| Product     | Quantity | Average cost |
|-------------|----------|---------------|
| 000000001   | 30       | 183.58        |
| 000000002   | 20       | 115.00        |
| 000000003   | 25       | 93.20         |
| 000000004   | 25       | 50.00         |
| 000000005   | 20       | 325.00        |

## Modern implementation

The modern implementation is located in:

- `modern/cost_calculator.py` — weighted average cost calculation
- `modern/legacy_parser.py` — parses the legacy input records
- `modern/historic_parser.py` — parses the COBOL historical output

## Equivalence validation

The test:

`tests/test_equivalence.py`

compares the actual output generated by the COBOL program with the
result produced by the modern Python implementation.

## Bug discovered during validation

During the initial validation, the COBOL program produced incorrect
results for products after the first control-break.

The root cause was the reuse of `WS-PRECIOCOSTO-N` in
`2200-GUARDAR-HISTORICO`.

The calculated average cost was moved into the same working variable
that was used for the current input cost:

```
MOVE WS-HR-COSTO-PROMEDIO TO WS-PRECIOCOSTO-N
```

This caused the calculated average from one product to become the
input cost used for the following product.

For example, the calculated average for product `000000001`
could become the first cost used when processing `000000002`.

## Fix

Dedicated temporary fields were introduced for historical output:

```
05 WS-HR-COSTO-TEMP     PIC 9(8)V99.
05 WS-HR-GANANCIA-TEMP  PIC 9(3)V99.
```

The historical output now uses these temporary fields instead of
overwriting the current input cost variables.

After the fix, the COBOL program produced the correct values and the
legacy-modern equivalence test passed.

## Significance for modernization

This baseline provides a behavioral reference for the modernization
process.

Instead of validating the modernization only by comparing source
code, the modern implementation can be validated against the actual
observable behavior of the legacy program.

The objective is therefore:

> Preserve business behavior first; modernize the implementation second.
